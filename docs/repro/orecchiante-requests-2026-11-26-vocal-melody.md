# 依頼 1: 録音の歌のメロディ（と歌詞）を `.lys` に（2026-11-26）

差出: Shosa のセッション。オーナーの依頼で出す（「Orecchiante を保守する AI セッションに依頼を出して」）。
入れるかどうか、どう入れるか、どの順かは Orecchiante 側とオーナーが決める。

## なぜ

Shosa の **Add a Dance…**（`.lys` の右クリック）は、曲を読んで Copilot のチャットに振り付けを頼む。振りを置く一番の手がかりは
**歌の音節がどの小節のどの拍に来るか**で、Shosa はそれを Lily# の `lysc timeline` の `sung`（Shosa → Lily# の依頼 6、
`[{part, singer, syllables: [[beat, beats, text]]}]`）から受け取り、`shosa song` で小節ごとに並べる（Shosa の DESIGN.md 123）。

Orecchiante で作った録音の `.lys` には小節線・コード・セクションはあるが、歌がない。オーナーが実際に
`We're An American Band.lys`（Orecchiante で作った、105 小節）に Add a Dance… を使うと、振付は通ったが
**退屈だった**（オーナー）: どのセクションも同じ 4 段の繰り返しで、腕の形が違うだけ。手がかりがセクションの名前と小節数しかないため。

## 頼みたいこと（段階。どこまでやるかは Orecchiante 側で）

1. **歌の音の始まりと長さを、歌のパートの音符に。** 分けたボーカル（`htdemucs_6s` の vocals、もうある）から。拍は Orecchiante が
   持っているので、それに寄せる。**振付に要るのは「音がどの拍で始まり、どれだけ伸びるか」だけ**で、音の高さは目安でよい
   （半音ずれても振付は困らない。ただし耳コピの役にも立つなら、そこは Orecchiante 側の判断で）。0.14.0 のベースで使った
   pYIN（C#）が使えるかもしれない。測るには手元の `scratch\real\rwc-annotations` のメロディの正解がある。
   - Lily# の `sung` は歌詞のある音だけを音節にするはずなので（Lily# の `docs/CLI_REFERENCE.md` の timeline で確かめて）、
     歌詞がないうちは**仮の歌詞**（例: 音ごとに `ら`／英語の曲なら `la`）を付けておくと、Shosa は何も変えずに使える。
     付けるかどうか、何にするかは任せる（口は仮の歌詞の母音で開閉する）。
   - 歌のパートが入ると、歌声のある譜として Lily# の歌声（Cantoria・NEUTRINO）が歌おうとするかもしれない。録音に重ねて鳴らさない
     形（`singer` を書かない等）が要るかは Orecchiante・Lily# 側で。
2. **貼った歌詞を音に割り当てる。** オーナーが歌詞を貼る → かな（モーラ）・英語は音節に分けて、1 の音符に 1 つずつ（強制アライメント）。
   日本語の漢字は Lily# の読みの書き方（`漢[かん]`）で。ここで Shosa のキャラクターの口が元の歌に合う。
   個人で楽しむ範囲の使い方（オーナー: 既存の曲は個人で楽しむ分には問題ない、著作権に留意）。
3. **歌詞の聞き取り（音声認識、Whisper など）** は要るなら。歌、特に日本語の歌の聞き取りは誤りが多いので、2 の予備の扱いでよい。
